# ملخص تطوير مشروع المنارة

## الهوية وتجربة الاستخدام

- الحفاظ على Hero وصورة الصفحة الرئيسية والثيم الأساسي.
- تعريب واجهات العرض والإضافة والتعديل والإدارة.
- استخدام Alexandria للعناوين وIBM Plex Sans Arabic للنصوص.
- إعادة تصميم الكتب والمؤلفين والأقسام والغرف بأسلوب موحد بعيد عن شكل الـ scaffold التقليدي.
- عرض العلاقات بأسماء بشرية بدل IDs أو تمثيل الكائنات البرمجية.
- دعم `dir="auto"` لأسماء الكتب والمؤلفين حتى تبقى بلغتها الأصلية.

## الدفع

- Braintree Sandbox رسمي بدل محاكي البطاقة اليدوي.
- Hosted Fields؛ بيانات البطاقة الخام لا تصل إلى Grails.
- سجل `Payment` موحد للدفع الأونلاين والكاونتر.
- شراء الكتاب لا يكتمل ولا ينقص المخزون قبل نجاح الدفع.
- الوصول الرقمي لا يُمنح قبل نجاح الدفع.
- العضوية لا تصبح فعالة قبل الدفع.

## غرف الدراسة

- لا يوجد RoomReservation بحالة PENDING.
- يتم تجهيز CheckoutIntent مؤقت فقط للـ checkout.
- بعد نجاح الدفع وإعادة فحص التوفر والعطلة والسعر ينشأ الحجز `CONFIRMED`.
- فحص التعارض يتم مرة عند التسعير ومرة أخرى داخل معاملة الدفع.
- خصومات مدة الحجز من `DiscountRule` قابلة للتعديل من الأدمن.
- صور، اسم، موقع، وصف وتجهيزات للغرفة.

## حجز واستعارة الكتب

التسلسل حسب حالة العضوية:

```text
WAITING → READY → PAID      → FULFILLED   (غير عضو)
               ↘ CONFIRMED → FULFILLED   (عضوية فعّالة)
```

- WAITING: حفظ دور المستخدم فقط، بدون دفع.
- READY: تم تخصيص نسخة مؤقتًا ويعاد حساب رسم الاستعارة على الخادم.
- PAID: غير العضو دفع `borrowingFee` لكن مدة الاستعارة لم تبدأ.
- CONFIRMED: العضو الفعّال أكد الاستعارة بدون رسوم وبدون Braintree.
- FULFILLED: تم التسليم وبدأت الاستعارة الفعلية لمدة 14 يومًا.
- رسوم التأخير تبقى مستقلة عن ميزة الاستعارة المجانية.
- يدعم الاستلام من المكتبة أو التوصيل.
- الأدمن يستطيع تنفيذ الدفع/التأكيد والتسليم من الكاونتر.

## العضوية

- 30+ يوم: 5%، 90+ يوم: 10%، 180+ يوم: 15%، 365+ يوم: 20%.
- العضوية التي تبدأ اليوم تصبح `ACTIVE` بعد الدفع؛ المستقبلية تصبح `SCHEDULED`.
- لا تمنح العضوية المجدولة أي مزايا قبل تاريخ البداية.
- يمنع النظام إنشاء فترة عضوية تتداخل مع عضوية فعّالة أو مجدولة.
- العضو الفعّال يحصل على استعارة ورقية بدون رسوم وعلى الكتب الرقمية المشمولة بالعضوية.

## اتساق البحث والـ REST API

- تم إصلاح بحث شاشة الكتب بحيث يبني HQL كـ `String` عادي مع parameters بدل GString، لمنع خطأ Hibernate `unexpected token: :`.
- الـ REST API يخفي الكتب غير الفعّالة عن المستخدم العادي مثل واجهة GSP.
- حذف كتاب له سجل عمليات يستخدم نفس قاعدة الـ business logic: تعطيل الكتاب بدل حذف التاريخ المرتبط به.

## المبيعات والكاونتر

- بيع أونلاين عبر Braintree Sandbox.
- بيع مباشر من الكاونتر بنقدي أو بطاقة كاونتر.
- حالات تجهيز منفصلة للاستلام والتوصيل.
- شراء رقمي يمنح DigitalAccess بعد الدفع فقط.

## التقويم

- Domain مستقل للعطل.
- Calendar إداري شهري.
- تعديل يدوي وإغلاق/فتح من الأدمن.
- مزامنة Holiday API لفلسطين `PS`.
- fallback محلي عند غياب API أو الإنترنت.
- تعديل الأدمن يحظى بالأولوية ولا تمسحه المزامنة الخارجية.

## بيانات الكتب الخارجية

- Google Books lookup حسب ISBN.
- Open Library fallback.
- تعبئة عنوان، مؤلفين مقترحين، ناشر، سنة، صفحات، لغة، وصف وغلاف عند توفرها.

## الصور

- صورة للمؤلف.
- صورة لغرفة الدراسة.
- أغلفة محلية أو غلاف خارجي للكتاب.
- حد رفع متوافق 5MB.

## الأمان والجودة

- Spring Security حسب الأدوار.
- Validation على السيرفر والواجهة.
- لا يتم تخزين Card Number أو CVV.
- Environment variables للمفاتيح السرية.
- منع حذف كيانات لها تاريخ عمليات؛ يتم تعطيلها عندما يكون الحذف غير مناسب.
- `toString()` بشري كـ fallback، مع عرض صريح للأسماء داخل GSP.
